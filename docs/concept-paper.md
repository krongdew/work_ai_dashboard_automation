# 📊 Concept Paper — MULA Data Automation Factory
### ระบบผลิต Dashboard อัตโนมัติด้วย AI สำหรับคณะศิลปศาสตร์ มหาวิทยาลัยมหิดล

> **หนึ่งบรรทัด:** เปลี่ยนไฟล์ Excel/Google Sheet ที่ "เละ" และกระจัดกระจาย ให้กลายเป็น Dashboard ที่ถูกต้องและพร้อมใช้ **ภายในไม่กี่นาที** โดยบุคลากรที่ไม่ต้องมีความรู้ด้านข้อมูล

---

## 1. 🔴 ปัญหา (Problem)

คณะศิลปศาสตร์มีข้อมูลที่ต้องติดตามจำนวนมาก แต่ติดกับดัก **data silo** และกระบวนการที่ใช้คนล้วน

| อาการที่เจอจริง | ผลกระทบ |
|---|---|
| ข้อมูลกระจัดกระจาย หลายรูปแบบ (Excel, Google Sheet) ไม่มีแหล่งจริงแหล่งเดียว | ตัวเลขขัดแย้งกัน ไม่รู้ว่าอันไหนถูก |
| ไฟล์จากระบบมหาวิทยาลัยมี **merge cell / header ไม่อยู่แถวแรก / ต้องกลับแถวเป็นคอลัมน์** | ต้อง clean ด้วยมือทุกครั้ง ใช้เวลานานมาก |
| บางชุดต้องดึงจากระบบ **หลายครั้ง** มาประกอบเป็นชุดเดียว | งานซ้ำซ้อน เสี่ยงพลาด |
| การทำ dashboard ใช้เวลานาน และข้อมูล **มักไม่ถูกต้อง** | ตัดสินใจบนข้อมูลที่เชื่อไม่ได้ |
| งาน IT มีภารกิจหลายด้าน ไม่ได้มีคนทำเรื่องนี้โดยเฉพาะ | คอขวดอยู่ที่คนไม่กี่คน |
| บุคลากรสายอื่นยัง **ไม่มีความรู้จัดการข้อมูล** | ทำเองไม่ได้ ต้องรอ IT |

**แก่นของปัญหา:** เวลาและความเชี่ยวชาญส่วนใหญ่หมดไปกับ **การทำความสะอาดไฟล์เพื่อให้ได้ master data** และ **การสร้าง dashboard** — ไม่ใช่การวิเคราะห์เพื่อตัดสินใจ

---

## 2. 🧭 บริบทองค์กร — Data Governance & MULA DataLink

คณะต้องการ **บริหารด้วยข้อมูลจริง (data-driven)** จึงริเริ่มโครงการ **Data Governance** เพื่อ:

- 🎯 รวมศูนย์ให้เป็น **Single Source of Truth** — ข้อมูลถูกต้อง ลด silo
- 👤 ทุกชุดข้อมูลมี **เจ้าของ (data owner)** ชัดเจน
- 🔐 **เข้ารหัสและรักษาความปลอดภัย** ของข้อมูล
- ⏱️ ลดเวลาการทำงานของเจ้าหน้าที่

จากนั้นพัฒนา **MULA DataLink** — แพลตฟอร์มรวมข้อมูล + dashboard ไว้ที่เดียว เชื่อมต่อ **BigQuery** เข้ารหัสได้ เก็บ dashboard ได้ และ **แบ่งสิทธิ์การมองเห็นตามบทบาท**

> **แต่ช่องว่างยังอยู่:** DataLink แก้เรื่อง "เก็บ/แบ่งสิทธิ์/รวมศูนย์" ได้ แต่ **ขั้นตอน clean ไฟล์ให้ได้ master data และสร้าง dashboard ยังต้องใช้คนที่มีทักษะและใช้เวลานาน** — จุดนี้เองที่ **Data Automation Factory** เข้ามาเติม

---

## 3. 💡 แนวคิดและวัตถุประสงค์ของ Solution

**MULA Data Automation Factory** = โรงงานผลิต dashboard อัตโนมัติ ที่ต่อยอดบน DataLink

**วัตถุประสงค์**
1. ให้บุคลากร **ที่ไม่มีความรู้ด้านข้อมูล** สร้าง dashboard ได้เองจากไฟล์ดิบ
2. **ย่นเวลา** จากหลักวัน/สัปดาห์ เหลือ **ไม่กี่นาที**
3. รับประกัน **ความถูกต้อง** ด้วยการแยก "AI วางแผน" ออกจาก "ระบบคำนวณ"
4. จัดการไฟล์ "เละ" (merge cell, header ไม่อยู่แถวแรก) ได้อัตโนมัติ
5. เชื่อมเข้า DataLink พร้อมสิทธิ์ตามหน่วยงาน

**หลักการออกแบบที่เป็นหัวใจ**

| หลักการ | ความหมาย |
|---|---|
| 🧮 **AI วางแผน — Python คำนวณ** | AI เสนอว่าควรมี KPI/กราฟอะไร แต่ **ตัวเลขทุกตัว Python คำนวณเอง** → ไม่หลอน ตรวจสอบได้ |
| 🔒 **Grounded เสมอ** | AI ใช้ได้เฉพาะชื่อฟิลด์จริงในข้อมูล ถ้าเสนอสิ่งที่ไม่มี ระบบปฏิเสธ + ซ่อมอัตโนมัติ |
| 🙈 **Privacy-first** | ส่งขึ้น cloud แค่ **metadata** (ชื่อคอลัมน์/ชนิด) ไม่ส่งข้อมูลรายแถว |
| 👁️ **ตรวจก่อนสร้าง** | แสดง master data + แผนวิเคราะห์ให้ตรวจก่อน แล้วค่อยสร้างจริง |

## 4. 👥 กลุ่มผู้ใช้ / ผู้ได้รับประโยชน์

| กลุ่ม | ได้ประโยชน์อย่างไร |
|---|---|
| 🧑‍💼 **ผู้บริหารคณะ** | เห็น dashboard ที่ถูกต้อง ทันเวลา ตัดสินใจบนข้อมูลจริง |
| 🧑‍🏫 **บุคลากรสายสนับสนุน/วิชาการ** | สร้าง dashboard เองได้โดยไม่ต้องรอ IT และไม่ต้องมีทักษะข้อมูล |
| 👨‍💻 **งาน IT** | ลดภาระงานทำ dashboard ซ้ำ ๆ ไปโฟกัสงานที่มีมูลค่าสูงกว่า |
| 🗂️ **เจ้าของข้อมูล (Data Owner)** | จัดการชุดข้อมูลของหน่วยตนเอง + คุมสิทธิ์การมองเห็น |
| 🏛️ **คณะ/มหาวิทยาลัย** | ขับเคลื่อน Data Governance ได้จริง ลด silo อย่างเป็นระบบ |

## 5. 🤖 แนวทางการประยุกต์ใช้ AI และ Kiro

### 5.1 บทบาทของ AI ในระบบ (ใช้แบบมีขอบเขต ตรวจสอบได้)

```
ไฟล์ดิบ ──▶ [Python] ตรวจโครงสร้าง + หา header จริง ──▶ master data
                              │
                              ▼
        [AI เบา] ตีความคอลัมน์ที่ไม่มีชื่อ (เช่น column_10 → "เดือน")
                              │
                              ▼
        [AI ฉลาด] วางแผน KPI / กราฟ / ตัวกรอง (เฉพาะวางแผน)
                              │
                              ▼
            [Python] คำนวณตัวเลขจริง + QA + เรนเดอร์ dashboard
```

- **Model tiering:** งานเบา (ตีความคอลัมน์, normalize) ใช้โมเดลเล็ก; งานวางแผนที่ต้องใช้เหตุผลใช้โมเดลใหญ่ → คุมต้นทุน token
- **Token pacing:** เว้นจังหวะเรียก AI อัตโนมัติให้อยู่ใต้โควตา ไม่ให้ระบบล่ม
- **รองรับทั้ง Cloud (Groq) และ Local (LM Studio)** — เลือกได้ตามความเป็นส่วนตัว/ต้นทุน

### 5.2 บทบาทของ Kiro (AI Agent)

Kiro ถูกใช้เป็น **คู่พัฒนา (pair-builder)** ตลอดการสร้างระบบนี้:
- ไล่อ่านโค้ด เข้าใจสถาปัตยกรรม และแก้ปัญหาจริง (header detection, rate limit, UI)
- ออกแบบและเขียนฟีเจอร์ทีละขั้นตามความต้องการของผู้ใช้
- ทดสอบ end-to-end และรายงานข้อจำกัดอย่างตรงไปตรงมา

> Kiro ทำให้ทีมเล็ก/ไม่มี dev เฉพาะทาง ก็พัฒนาและดูแลระบบระดับ production ได้

## 6. ⚙️ สิ่งที่ Prototype ทำได้แล้ว (ของจริง)

- ✅ **ตรวจ header อัตโนมัติ** — ไฟล์ merge cell / header ไม่อยู่แถวแรก ระบบหาแถวหัวตารางจริงให้เอง
- ✅ **AI ตีความคอลัมน์ที่ไม่มีชื่อ** — `column_10` ที่ค่าเป็น ส.ค./พ.ย. → ตั้งชื่อให้เป็น "เดือน"
- ✅ **แสดง master data ให้ตรวจก่อนสร้าง** — เห็นหน้าตาข้อมูล + คุณภาพ (ค่าว่าง, ซ้ำ, วันที่แปลงไม่ได้)
- ✅ **สร้าง dashboard 3 รอบ** (วิเคราะห์ → master data → dashboard) มี progress ทุกขั้น
- ✅ **แก้ไข dashboard ด้วยคำสั่งภาษาไทย** — เพิ่มกราฟ/ตัวกรอง/KPI/เปลี่ยนวิธีคำนวณ
- ✅ **สิทธิ์ตามหน่วยงาน/หน่วยย่อย** + ระดับการมองเห็น (ในหน่วย / ทั้งคณะ / สาธารณะในองค์กร)
- ✅ **ส่งออก DataLink Bundle** — ชุดข้อมูล+สเปก+QA พร้อมนำเข้า DataLink

## 7. 🌟 คุณค่าและโอกาสในการนำไปใช้จริง

| มิติ | ก่อน | หลัง (ด้วย Factory) |
|---|---|---|
| ⏱️ เวลา/ชิ้นงาน | หลายชั่วโมง–หลายวัน | **ไม่กี่นาที** |
| 🎓 ทักษะที่ต้องมี | ต้องเชี่ยวชาญข้อมูล | **ไม่ต้องมีก็ทำได้** |
| ✅ ความถูกต้อง | พึ่งการ clean ด้วยมือ | **Python คำนวณ + QA อัตโนมัติ** |
| 🔑 การเข้าถึง | รวมที่คน IT | **กระจายให้ทุกหน่วยทำเองได้** |

**โอกาสขยายผล**
- ขยายจากคณะศิลปศาสตร์ → **ทุกคณะ/ส่วนงาน** ของมหาวิทยาลัย
- ต่อยอดเป็นมาตรฐานการทำ dashboard ของ Data Governance ทั้งองค์กร
- รองรับแหล่งข้อมูลเพิ่ม (ฐานข้อมูล, API ของระบบมหาวิทยาลัย)

## 8. 🚧 ข้อจำกัดที่ทราบ & ทิศทางต่อไป

- ไฟล์ที่ **ไม่มี header เลยจริง ๆ** ยังต้องให้ผู้ใช้ช่วยตั้งชื่อคอลัมน์ (กำลังเพิ่ม UI ให้แก้เอง)
- โมเดล cloud มีโควตา token ต่อนาที — มีระบบเว้นจังหวะรองรับ และสลับไป local ได้
- แผนถัดไป: เชื่อม DataLink แบบ push ตรง, เทมเพลต dashboard สำเร็จรูป, ตั้งเวลาอัปเดตอัตโนมัติ
