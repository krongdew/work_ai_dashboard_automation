THEME RULE

All dashboards generated by this skill MUST follow the configured
institutional theme.

The agent MUST NOT:
- randomly choose colors
- introduce gradients
- use neon colors
- use 3D charts
- use decorative backgrounds
- change the primary color system
- use inconsistent card styles

The agent MAY:
- choose different chart types based on the data
- adjust chart density
- change layout based on dashboard purpose
- use semantic colors for success/warning/danger
- use accent colors sparingly

The dashboard must remain visually recognizable as part of
the same dashboard system even when the dataset changes.

HEADER AND CHART RULES

- Display `dashboard-automation/assets/logo.png` in every dashboard header.
- Use a flat white institutional header with the Faculty of Liberal Arts,
	Mahidol University identity: logo at left, Thai/English faculty name, centered
	dashboard title, and a restrained gold border or accent.
- Show readable value labels for line-chart points; abbreviate large values
	only when necessary for legibility and retain exact values in tooltips.
- Use the categorical chart palette in sequence for categories. Do not render
	every bar, line point, or pie slice in the same color when more than one
	category is visible. A chart must show both category label and formatted
	value: direct labels for bars and line points, and a label/value/percentage
	legend for pie charts.
- Calculate each pie slice as `category value / sum of all displayed category
	values`; never scale pie slices against the largest category.
- KPI cards use semantic year-over-year indicators: green upward arrow when
	higher is favorable, red downward arrow when lower is favorable. For cost or
	other lower-is-favorable metrics, reverse the favorable direction. Always
	show the comparison period and `ไม่มีฐานเปรียบเทียบ` when unavailable.
- Chart categories are interactive filters. Selecting a bar or point updates
	all KPI cards, charts, and tables; provide a clear control to remove the
	selection. This interaction must work without relying on color alone.
- Clicking an already selected bar or point must clear that chart filter.
- Bar and line charts must label their category axis and metric axis. Show the
	category and formatted value on every visible mark; rotate labels only when
	needed to prevent overlap.
- Trend/column charts must place category labels on the X-axis beneath each
	column and values immediately above columns. Use restrained horizontal grid
	lines and a visible numeric scale; do not place rotated labels over marks.
- Comparison bar charts use a readable axis orientation: category labels align
	with the bars, values sit at bar ends, and a zero-to-maximum scale is visible
	behind the bars.
- Place a compact calculation-details control in the chart's top-right corner.
	Activating it must show source field, dimension, formula, input rows, active
	filters, and limitations in visible text, not only a browser tooltip.
- Detail tables must offer a `ต้องตรวจสอบ` view for missing values, values
	that failed normalization, and suspicious numeric values so users can repair
	source data.
